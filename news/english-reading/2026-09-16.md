Why AI Chips Are Running Into a Memory Problem

The fastest artificial intelligence chips are often described by the number of calculations they can perform each second. That sounds natural. If a processor can do more mathematical operations, it should finish an AI task more quickly. But modern AI systems have created a less obvious problem: a chip can be ready to calculate while still waiting for the data it needs.

This is known as the memory bottleneck. It is becoming one of the most important limits on AI performance, and it explains why a type of memory called high-bandwidth memory, or HBM, has become so valuable.

An AI accelerator such as a graphics processing unit contains thousands of small computing units. During the training or operation of a large language model, those units repeatedly read model parameters and other data from memory, perform calculations, and write new results. If memory cannot supply data quickly enough, some computing units sit idle. Adding more computing power does not fully solve the problem because the processor is still waiting.

A useful comparison is a factory. Imagine that a factory installs twice as many machines but keeps the same narrow road for delivering materials. The machines are technically more powerful, yet the road becomes the real limit. In an AI system, memory bandwidth is similar to the width of that road. It measures how much data can move between memory and the processor in a given time.

This is why recent AI accelerators have placed unusual attention on memory. Nvidia's H200 accelerator, for example, introduced HBM3E memory with 141 gigabytes of capacity and memory bandwidth of 4.8 terabytes per second. AMD's later Instinct MI355X offers 288 gigabytes of HBM3E and theoretical memory bandwidth of up to 8 terabytes per second. These large numbers are not simply marketing details. They show how strongly AI performance now depends on moving data, not only on calculating with it.

HBM is designed differently from the ordinary memory found in most desktop computers. Standard memory modules usually place chips beside one another on a circuit board. HBM stacks several layers of dynamic random-access memory vertically. Tiny electrical paths called through-silicon vias run through the stack, allowing data to travel between layers. The memory is also placed very close to the processor inside the same package.

This design has two major advantages. It creates a very wide path for data, and it shortens the physical distance the data must travel. Micron says its HBM3E products can provide more than 1.2 terabytes per second of bandwidth from a single memory stack. Its newer HBM4 generation raises that figure to more than 2.8 terabytes per second per stack. HBM can also use less energy for each bit of data moved because the electrical connections are shorter.

That matters because moving data has a real energy cost. In a large data center, a small improvement in efficiency can become important when thousands of accelerators operate continuously. Faster memory can also allow expensive processors to spend more time doing useful work instead of waiting.

Large language models make the problem especially serious. A model may contain billions of numerical values that represent what it learned during training. When the model answers a question, many of those values must be read again and again. AI systems also create temporary information while processing long conversations. As models handle longer documents, images, audio, video, and complex reasoning tasks, both memory capacity and memory bandwidth become more important.

This helps explain why companies cannot improve AI hardware simply by building faster computing cores. The whole system must develop together. Processor design, memory, packaging, cooling, networking, and software all affect the final speed. A powerful accelerator with weak memory can waste part of its computing ability. A well-balanced system may achieve better real-world performance even if one individual specification looks less impressive.

The growing importance of HBM has also changed the semiconductor business. Memory was once treated by many observers as a less glamorous part of computing than processors. The AI boom has challenged that view. Companies such as SK Hynix, Samsung, and Micron are now central players in the AI supply chain. Reuters has reported continuing pressure on HBM supply as data-center companies expand AI infrastructure. In 2026, shortages were serious enough to affect the cost and availability of some AI accelerators.

Producing HBM is difficult. Manufacturers must build many thin memory dies, test them carefully, stack them with high precision, and connect them through thousands of tiny vertical links. The final memory stacks must then be placed close to advanced processors using complex packaging methods. A defect in one part of the stack can reduce manufacturing yield, which makes rapid expansion harder than simply building more ordinary memory.

There are also limits to how far HBM can solve the problem. Faster memory is expensive, and adding more capacity increases packaging and cooling challenges. Engineers are therefore exploring other approaches as well. Software can reduce the amount of data that must move. Models can use lower-precision numbers, smaller caches, or techniques that avoid loading unnecessary information. Some systems divide a model across many processors and rely on extremely fast connections between them.

The deeper lesson is that computing performance is rarely determined by one component. For years, people became used to thinking about faster processors as the main measure of progress. Artificial intelligence is making the balance between computing and data movement much more visible.

The next generation of AI may depend as much on getting information to the processor at the right moment as on making the processor itself faster. In that sense, the race to build better AI chips is also becoming a race to build better roads for data.
