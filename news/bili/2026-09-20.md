<h2 class="bili-daily-section">软件、云服务与安全</h2>

<div class="bili-daily-item">
<h3><span class="bili-daily-index">09</span>SageMaker HyperPod 推出 GPU-aware Inference Gateway，AWS 称首 Token 延迟最高降 82%</h3>
<p>AWS 发布 Amazon SageMaker HyperPod Inference Gateway。这是面向 Amazon EKS 的 Kubernetes 原生 GPU 感知路由组件，可结合实时 GPU 状态、KV Cache、LoRA 适配器等信息选择更合适的推理 Pod。AWS 基准称，在其测试条件下首 Token 延迟最多降低 <span class="bili-daily-metric">82%</span>，且不要求修改模型服务器或客户端应用。</p>
<p class="bili-daily-meta">发布时间：2026年9月18日</p>
<p class="bili-daily-source">来源：<a href="https://aws.amazon.com/blogs/machine-learning/introducing-amazon-sagemaker-hyperpod-inference-gateway/">AWS 官方博客</a></p>
<p class="bili-daily-why"><strong>为什么值得关注：</strong>大模型推理中，普通 round-robin 路由看不到 KV Cache 与 GPU 忙闲状态，容易造成昂贵显卡空闲或请求排队。GPU-aware 路由直接瞄准推理集群利用率与首 Token 延迟。</p>
</div>

<div class="bili-daily-item">
<h3><span class="bili-daily-index">10</span>Vercel 披露 libheif RCE 修复全过程：恶意 AVIF 可沿 Next.js 图像优化链触发漏洞</h3>
<p>Vercel 在9月18日公开此前 libheif 远程代码执行漏洞的复现与协调修复过程。漏洞并不位于 Next.js 本身，而是在 AVIF 解码依赖 libheif 中，但可通过 <code>next/image</code> → sharp → libvips → libheif 的链路到达。Vercel 表示其平台已在8月13日部署缓解措施，libheif <span class="bili-daily-metric">v1.23.2</span> 于8月25日完成修复，Next.js 同期发布安全更新。</p>
<p class="bili-daily-meta">技术披露发布时间：2026年9月18日；漏洞修复时间：2026年8月25日</p>
<p class="bili-daily-source">来源：<a href="https://vercel.com/blog/reproducing-disclosing-and-fixing-the-libheif-vulnerability-with-hacktron-and-the-maintainers">Vercel 官方安全博客</a></p>
<p class="bili-daily-why"><strong>为什么值得关注：</strong>这不是单一框架漏洞，而是典型的图像解码供应链风险。自托管 Next.js、sharp、ImageMagick 等依赖 libheif 的服务，应确认已使用修复后的依赖链；Vercel 托管项目则已由平台侧缓解。</p>
</div>

<div class="bili-daily-item">
<h3><span class="bili-daily-index">11</span>Google 披露内部安全 Agent 实践：自动扫描大规模代码变更</h3>
<p>Google Cloud 官方介绍了其使用 AI Agent 保护基础设施的内部实践：Agent 被用于检查跨大规模代码库的变更、寻找潜在安全问题，并把发现送入现有安全流程。Google 表示，这类系统已经用于覆盖数亿行代码规模的变更检查。</p>
<p class="bili-daily-meta">发布时间：2026年9月18日</p>
<p class="bili-daily-source">来源：<a href="https://cloud.google.com/blog/topics/systems/using-ai-agents-to-secure-google-infrastructure">Google Cloud 官方博客</a></p>
<p class="bili-daily-why"><strong>为什么值得关注：</strong>安全 Agent 的价值不在“替代审计员”，而在把原本无法逐次人工覆盖的海量代码变更提前筛查，再把高风险项交给现有安全体系复核。这是 Agent 进入大型软件供应链的具体落地方式。</p>
</div>

<div class="bili-daily-item">
<h3><span class="bili-daily-index">12</span>Cloudflare Browser Run 增加 Inspect：可直接回看日志、网络请求和最终 DOM</h3>
<p>Cloudflare 为 Browser Run Session Recordings 增加 Inspect 面板。录制后的浏览器会话现在可查看 Console Logs、完整 Network 请求与时间瀑布、最终 DOM，并可导出 HAR；网络活动也能通过 API 获取为 JSON 或 HAR。</p>
<p class="bili-daily-meta">发布时间：2026年9月18日</p>
<p class="bili-daily-source">来源：<a href="https://developers.cloudflare.com/changelog/post/2026-09-18-browser-run-session-recording-inspect/">Cloudflare 官方 Changelog</a></p>
<p class="bili-daily-why"><strong>为什么值得关注：</strong>浏览器 Agent 最难调试的往往不是“最后页面长什么样”，而是中间发生了哪些请求、脚本错误和 DOM 变化。把这些信息和会话录像绑定，可明显缩短复现失败任务的时间。</p>
</div>

<div class="bili-daily-item">

<p class="bili-daily-meta">发布时间：2026年9月18日</p>

</div>
